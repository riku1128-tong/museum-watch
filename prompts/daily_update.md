# 美術館ウォッチ 週次更新の手順書（毎週金曜）

あなたは museum-watch の毎週の巡回担当。作業フォルダはこのリポジトリのルート（`prompts/` の 1 つ上）。
全国の美術館の公式サイトを読み、`data/details/<id>.json` を最新にしてから `docs/index.html` を作り直す。
ユーザーは寝ているので質問はしない。判断に迷ったら「推測で埋めずに unknown / confidence を下げる」側に倒す。

## 0. 使用量を記録する

`mcp__ccd_session_mgmt__get_usage` が使えるなら、最初に呼んで「Weekly · all models」の `percentUsed` を控える（巡回前の値）。
4 の直前にもう一度呼んで巡回後の値を控え、`render.py` に `--weekly-before <前> --weekly-after <後>` で渡す。
ツールが無い・読めないときは省略してよい（巡回は止めない）。

## 1. 計画を作る

```bash
date -Iseconds                       # 開始時刻を控えておく（最後に --started へ渡す）
uv run scripts/plan_run.py > "$TEMP/museum_plan.json"
```

`batches` は館をおよそ 8 館ずつに分けた配列（まだ巡回していない館は 1 回 100 館まで。残りは `waiting` 館として次回以降に回る）。各館には `mode` がある。
- `full`: 利用案内・展覧会・お知らせをすべて読み直す
- `light`: トップとお知らせ（ニュース）だけ見て、臨時休館・新しい展示・時間変更の有無を確かめる

館が 0 件なら 4 に進む。

## 2. バッチごとにサブエージェントを並列に起動する

`Agent` ツール（subagent_type: `general-purpose`）で、**全部のバッチを 1 回のメッセージで同時に**起動する。
各エージェントへのプロンプトは次の形にする（`<ルート>` は `pwd` で確かめた絶対パス。担当バッチの JSON はそのまま貼る）:

```
<ルート>/prompts/daily_update.md の「サブエージェント用の指示」の節を読んで、そのとおりに作業して。
担当する館: <バッチの JSON>
```

戻ってきた報告から、`partial` / `failed` になった館の id を集めておく。

## 2.5 取れなかった館をやり直す（「不明」を残さない）

```bash
uv run scripts/plan_run.py --retry > "$TEMP/museum_retry.json"
```

`--retry` は、開館時間が空・`operating_status` が unknown・`confidence` が low の館を返す。1 館でもあれば、
サブエージェントを 1 館に 1 つずつ（最大 8 つ並列）起動し、プロンプトの末尾に「**再挑戦モード**」と書き添える。
再挑戦でも取れなかった館だけを failed にする。

## 3. 検証する

```bash
uv run scripts/validate.py
```

NG が出た館は、エラーの内容を見て JSON を直接直す（スキーマは `schema/detail.schema.json`）。
2 回直しても通らない館は、`confidence: "low"` にしたうえで `regular_hours: []` と `operating_status: "unknown"` にして通し、failed として扱う。

## 4. ページを作り、ログを残す

```bash
uv run scripts/render.py --log --started <1で控えた時刻> --failed <失敗idをカンマ区切り>
```

## 5. 公開ページを更新する

`validate.py` がすべて OK のときだけ、`data/` と `docs/` の変更をコミットして main にプッシュする（GitHub Pages が更新される）。
コードや手順書（`scripts/` `prompts/` `schema/` など）はコミットに含めない。NG が残っているときはプッシュせず、報告に書く。

```bash
git pull --ff-only
git add data docs
git commit -m "データ更新 $(date +%F)" -m "Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>"
git push
```

変更が無くてコミットできないときは、そのまま次へ進む。push に失敗したら、エラーを報告に書く（force push はしない）。

最後に、次の内容を 3〜5 行で報告して終わる: 開館館数、休館館数、不明館数、失敗した館、目立った変化（新しい展示・臨時休館）、プッシュしたかどうか。

## サブエージェント用の指示

あなたは美術館の情報を集める担当。渡されたバッチの館について、公式サイトを WebFetch で読み、
リポジトリの `data/details/<id>.json` を書く（既にあれば読み込んでから更新する）。
形式は `schema/detail.schema.json` に従う。最初にスキーマを読むこと。
今日の日付は `date +%F` で確かめる（JST）。

### 読む場所
- 基本の情報源は公式サイト（`official_url`）。公式 URL が無い・つながらない場合は、WebSearch で公式サイトを探して `official_url` に入れる。
  口コミサイト・個人ブログ・SNS の個人投稿は使わない。
- `full`: トップ → 「利用案内 / ご来館の方へ / 開館時間 / 観覧料 / アクセス」 → 「展覧会 / 開催中 / 今後の予定」 → 「お知らせ / ニュース」の順に読む。休館日カレンダーがあれば必ず読む。
- `light`: トップとお知らせだけ読む。変化が無ければ、既存の JSON の `checked_at` と `check_mode` だけ更新する。
  変化がある（新しい展示、臨時休館、時間変更、閉館・休館の告知）場合は、その部分を直す。大きな変化なら `full` と同じように読み直してよい。
- **「不明」を残さないのが目標。** トップが読めなくても、すぐにあきらめない。次の順で別の入口を試す:
  1. 公式サイトの別ページ（`/guide/` `/access/` `/visit/` `/info/` `/exhibition/` `/schedule/`、英語版ページ、`/sitemap.xml`）
  2. WebSearch で「<館名> 開館時間 休館日」「<館名> 展覧会 2026」を検索し、公式サイト内の該当ページを直接読む
  3. 自治体・運営財団の公式ページ（公立館は区市町村のサイトに施設案内がある）
  4. それでも公式が読めないときだけ、信頼できる美術情報サイト（インターネットミュージアム、Tokyo Art Beat、美術手帖）を使ってよい。
     その場合は `source_urls` に入れ、`confidence` は `medium` にする
- 1 館あたりの WebFetch は、full で 8 回、light で 3 回、再挑戦モードで 15 回までにする。お知らせに「開館時間の変更」「臨時休館」などの記事があれば、その本文を優先して読む。
- WebFetch には「開館時間・休館日・臨時休館・開催中と今後の展覧会（タイトル・会期・URL）を、**日本語の原文のまま**（翻訳しない）抜き出して」と頼む。

### 書き方のルール
- `checked_at`: 今の時刻（`date -Iseconds`、+09:00 付き）。`check_mode`: `full` か `light`。
- `operating_status`:
  - 通常営業中は `operating`
  - 改修などで長期休館中（数か月単位）は `temporarily_closed`。`status_note` に再開予定を書く
  - 閉館済みは `permanently_closed`
  - 読めなかったときは `unknown`
- `regular_hours`: 曜日ごと・期間ごとの時間。例: 「金・土は20時まで」なら 2 つのエントリに分ける。季節で変わる場合は `from` / `to` を付ける（夏期・冬期など）。
  上書きの書き方は 2 通りあり、どちらも使ってよい: 「全曜日 10-18 ＋ 金曜 10-20」（対象曜日が少ない方が優先）、
  「通常 10-18 ＋ `from`/`to` 付きの 12/7〜12/10 は 10-20」（期間が狭い方が優先）。同じ曜日・同じ期間に 2 つ書くのは不可。
  `days` の `holiday` は、祝日だけ時間が違うときに使う。`last_entry` は「入館は閉館の30分前まで」なら計算して入れる。
- `closed_weekdays`: 毎週の定休日の曜日（例: 月曜休館 → `["mon"]`）。定休日が無ければ `[]`。
- `closed_nth_weekdays`: 「第1・第3月曜休館」のような第n週の定休日 → `[{"weekday": "mon", "nth": [1, 3]}]`。
  **規則から日付を計算して `special_closures` に並べてはいけない**（判定は render.py がする）。
- 館全体の休館日と、展覧会（展示室）だけの休室日は分けて書く。館は開いていて特別展だけ毎週月曜休室なら、
  館の `closed_weekdays` には入れず、その展覧会の `closed_weekdays: ["mon"]` に入れる。展覧会だけの振替休室日は、展覧会の `closed_dates` に入れる。
- `holiday_rule`: 定休日が祝日と重なったときの扱い。
  - 「月曜休館（祝日の場合は開館し、翌平日休館）」→ `open_next_weekday_closed`
  - 「月曜休館（祝日の場合は開館）」で振替の記載なし → `open`
  - 「祝日休館」→ `closed`
  - 年中無休・定休日なし → `open`
  - 記載が無い → 休館日カレンダーで祝日の扱いを確かめる。それでも分からなければ `unknown`
- `special_closures`: 年末年始・展示替え・メンテナンスなど、公式に日付が書かれている休館期間だけ入れる。今日より 7 日以上前に終わった期間は消す。
  年末年始の休館は、公式に日付が出ていれば必ず入れる（無いと年末に「要確認」が付く）。
  「展示替えのため休館」と期間が明記されていれば、ここに入れる。
- `closed_between_exhibitions`: 企画展だけで運営していて、会期と会期の間は休館する館なら `true`（常設展が無い館によくある）。
- `special_openings`: 定休日でも館として臨時で開館する日。展覧会ページにだけ「木曜休館（ただし9/24は開館）」とある場合も、館が開くならここに入れる。
  「10/12(月・祝)は開館」のように holiday_rule から出るものは入れない。
- `exhibitions`: 開催中のものと、今後 3 か月以内に始まる展覧会。常設展・コレクション展は `kind: "collection"`、企画展・特別展は `special`。
  `title` は公式表記どおりにする（「～」「―」などの区切りも公式のまま）。「開館100周年記念」のような冠は外してよい。
  `summary` は 60 字以内で内容を要約する（作家名・テーマ）。
  `admission` は一般料金だけを短く書く（例: 「一般 2,300円」）。展覧会ごとではなく館共通の入館料なら、その額を各展示に入れてよい。展覧会だけ時間や休館日が違う場合は、`hours` / `closed_weekdays` / `closed_dates` を付ける。
  会期が「〜未定」「通年」の常設展は、`end` を今日から 1 年後にし、`summary` に「通年」と書く。終わった展示は消す。
- `adult_price`: 館の入館料（常設展・コレクション展）の**大人一般**の料金（円、整数）。無料なら 0、常設展が無く企画展ごとの料金だけの館は null。
  展覧会ごとの大人一般料金は、各展覧会の `adult_price` に整数で入れる（`admission` の文字列も残す）。前売・団体・割引の料金は入れない。
- `free_days` / `free_rules`: **大人一般が無料**になる日。65 歳以上・高校生以下だけの無料は含めない。
  - 日付が決まっているもの（都民の日 10/1、国際博物館の日 5/18、文化の日 11/3、開館記念日など）→ `free_days` に `from`/`to`
  - 毎月・毎週の規則（毎月第 1 日曜、毎月 18 日 など）→ `free_rules` に `weekday`+`nth` または `day_of_month`
  - `scope` は、企画展も含めて無料なら `all`、常設展・コレクション展だけ無料なら `collection`
  - 東京都の都立美術館・博物館は、都民の日（10/1）に常設展などが無料になることが多い。公式に書いてあるときだけ入れる
- `access`: 最寄駅を近い順に最大 3 つ。`station` は駅名（「駅」は付けない）、`lines` は路線名、`exit` は出口、`walk_min` は徒歩分数。
  バスが主な行き方の館は、`note` に「〇〇駅からバス15分」のように書く。
- `address`: 住所（郵便番号付きでよい）。`source_urls`: 実際に読んだ URL。
- `confidence`:
  - 開館時間・定休日・展示の 3 つとも公式サイトで確認できたら `high`
  - 一部が推定なら `medium`
  - 読めなかった（JS で描画される・403・タイムアウト）なら `low`
- **推測で埋めない。** 読めなかった項目は、前回の値があれば残して `confidence` を下げ、無ければ空配列や `unknown` にする。
  とくに、日付や時刻をでっち上げてはいけない。
- 書き終えたら、リポジトリのルートで `uv run scripts/validate.py <id> ...` を担当分について実行し、NG があれば直す。

### 報告
最後に、担当した館ごとに 1 行で報告して終わる:
`<id> <館名> ok|partial|failed <開館時間の要約> / 展示 <件数>件 / <変化や注意点>`
